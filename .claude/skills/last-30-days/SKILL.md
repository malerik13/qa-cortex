Ты генерируешь **ежемесячный QA отчёт** по данным из YouTrack, Allure и journal. Выдаёшь HTML дашборд (аналог Cockpit, но за период).

**Language**: chat RU / HTML artifacts EN (per language matrix).

---

## Phase 1 — Parallel data load (R1)

Запускай все 4 параллельно (single message, 4 tool calls):

```
DATE_FROM = today - 30 days  (format: YYYY-MM-DD)

1. youtrack:search_tickets — filter: "created: {DATE_FROM} .. today AND type: Bug AND project: [COMPANY]"
   → вытянуть: id, summary, severity, status, created, assignee, affectsVersion

2. youtrack:search_tickets — filter: "updated: {DATE_FROM} .. today AND type: User Story AND assignee: me AND state: Verified"
   → вытянуть: id, summary, resolved date

3. Bash: grep -rh "^\- \[" journal/ --include="*.md" | grep -v dev/ | tail -200
   → последние 200 journal entries (log/bug/blocker/status)

4. allure:list_recent_test_cases — limit: 50, filter by last 30 days if supported
   → OR: Bash: python3 -c "import json; data=json.load(open('knowledge_base/test_cases.json')); ..."
```

После загрузки → агрегируй в память. Не пиши в qa-output до Phase 3.

## Phase 2 — Analysis (R2)

Из данных R1 извлеки:

### Bug metrics
- Всего багов за период: N
- По severity: Critical=X, Major=Y, Normal=Z, Minor=W
- По статусу: Open=X, Fixed=Y, Closed=Z, Won't Fix=W
- Топ-3 модуля по багам (из ticket summary/component)
- 1st cohort count (теги в YouTrack или признак из journal)
- Среднее время Fix (created → Fixed, для Fixed багов)

### Testing coverage
- Verified User Stories: N
- Tested but not verified: N
- Journal entries: log=X, bug=Y, blocker=Z

### Pattern signals
- Повторяющийся модуль в 3+ багах → "regression risk area"
- Severity trend (больше Critical чем предыдущий месяц?) — если нет данных за прошлый месяц, пропусти
- 1st cohort % > 30% → "smoke coverage gap signal"

## Phase 3 — Generate HTML report

Генерируй HTML файл `qa-output/report-30d-{DATE}.html` со следующими секциями:

### Обязательные секции:
1. **Header** — период, дата генерации, ссылка на YouTrack project
2. **Stats cards** — Bugs Total / Critical / Open / Verified Stories (4 карточки с цветами)
3. **Bug cluster table** — все баги периода, с колонками: ID (linked) / Summary / Severity (badge) / Status (badge) / Module / Filed date
4. **Coverage summary** — progress bars: Verified Stories / Journal entries by type
5. **Pattern signals** — предупреждения если regression risk или smoke gap
6. **Top modules at risk** — топ-3 модуля по числу багов
7. **Footer** — "Generated by [company]-qa-assistant · {timestamp}"

### HTML стиль:
Используй тот же dark theme что в `qa-output/cockpit-demo.html`:
- `--bg: #0f1117`, `--surface: #1a1d27`, `--accent: #6c8ef5`
- Severity badges: Critical=red, Major=orange, Normal=yellow, Minor=blue
- Status badges: Open=red, Fixed=green, Closed=gray, Verified=purple
- Все ID = кликабельные ссылки на `https://[company].youtrack.cloud/issue/{ID}`

## Edge cases

- Если YouTrack search вернул 0 результатов → выведи "No data" но HTML всё равно генерируй
- Если journal/ пуст за период → раздел Coverage показывает нули, добавь note "Journal not populated"
- Если allure данных нет → раздел Test Cases пропускаем (не придумываем)
- Если preview сервер уже запущен (port 8765 occupied) → reuse, не перезапускать
