# HOWTO — Daily playbook для работы с qa-brain

> Шпаргалка на каждый день. Открыта на ноуте, печатать на принтере опционально.
> Не заучивать — просто делать по схеме первую неделю, дальше станет автоматом.

---

## 🌅 Утро (09:00–10:00) — старт дня

**Открой новый чат.** Скажи **естественной речью**:

```
доброе утро
что у нас сегодня
утренний брифинг
```

→ Orchestrator persona активируется (по triggers в CLAUDE.md routing) → читает journal вчера, тянет YouTrack по твоим тикетам, выдаёт дайджест: вчера / сегодня / блокеры / план дня.

---

## 🎯 Старт работы по тикету (после брифинга)

Из плана дня выбираешь один тикет → **открываешь новый чат** → говоришь **естественной речью**:

```
Тестируем {TICKET_PREFIX}-XXXXX
```

или просто кидаешь URL:
```
https://[your-domain]/issue/{TICKET_PREFIX}-XXXXX/...
```

или для re-test после фикса:
```
Full re-test {TICKET_PREFIX}-XXXXX staging + release
```

→ Skill `start-ticket-test` активируется автоматически. Brain параллельно тянет: ticket + linked + comments + Allure cases (с шагами!) + insights + bugs.json. Через 1-2 минуты выдаёт **Bridge** + **15-line summary**. Останавливается на твоём review перед Phase 1.5.

Дальше идёшь по фазам, brain ведёт. Когда хочешь сохранить — скажи **«сохрани»** или **«save»** в текущем чате.

---

## 📌 По ходу работы (фоновое)

Brain сам логгирует значимые шаги в `journal/_active.md`. **Тебе ничего не надо делать**, но если хочешь явно — можно:

```
журнал: проверил что email_templates отсутствует на release — баг подтверждён
```

При каждом filed bug brain автоматом запишет в журнал (это незыблемое правило).

---

## 💬 Quick-questions в течение дня

Если просто посмотреть статус, не делать full Phase 1 — **тот же чат, не новый**:

```
статус по {TICKET_PREFIX}-12345
что в работе у меня
расскажи про KYC documents flow
```

Если вопрос на час+ ушёл в дебри — **закрывай этим чатом, открывай новый** под нужную миссию.

---

## 🌅 Конец рабочего дня (17:00–18:00)

В **текущем** чате (не новом) — скажи:

```
save
сохрани
сохрани в дейлик
```

→ Brain записывает Session N в `journal/<DATE>.md`, сбрасывает `_active.md`. Готов к завтра.

---

## 🌙 На завтрашнем стендапе

В новом чате утром:

```
стендап
дейлик
готовь спич на стендап
```

→ Brain собирает Slack-формат: «Вчера ... / Сегодня ... / Блокеры ...». Копируешь, постишь сам в #qa.

## 🚨 Особые ситуации

### Brain тупит, повторяется, путается
```
ты второй раз про это — освежить контекст?
```

или просто:
```
save и закрываюсь — открою новый чат
```

→ Откроешь новый, brain прочитает journal с твоими работами и подхватит.

### Срочный баг, нет времени на Phase 1
```
оформи баг про <одно предложение что сломалось>
```

или:
```
/bug <описание>
```

→ Brain делает только Phase 4 (defect handling). Покажет draft → ты говоришь "yes create on release" → создаётся.

### Ничего не помню что было вчера
```
расскажи что я делал вчера
```

или:
```
/standup
```

→ Brain читает `journal/<вчера>.md` и пересказывает.

### Хочу что-то понять / разобрать
Если в любом чате говоришь:
```
объясни что такое equivalence partitioning
расскажи про severity vs priority
не понимаю как boundary value analysis работает
```

→ Orchestrator активирует ISTQB-знания (per `orchestrator_persona.md §10` ISTQB foundation). Объясняет 6-8 строк, anchor к [COMPANY]-примеру. Если хочешь глубже — скажи, иначе закроет тему.

**Orchestrator сам не предлагает** — только когда ты явно спрашиваешь. Никаких proactive teaching offers.

## 📋 Правила гигиены (соблюдай — brain будет работать долго)

| Правило | Почему |
|---|---|
| **Один чат = одна миссия** | Если переключился на другой тикет — закрой save, открой новый |
| **Save перед уходом** | Иначе работа невидима для утреннего брифинга завтра |
| **Не переоткрывай старые чаты** | Лучше новый чат + journal как continuity. Старый чат разрастается, тупеет |
| **Если brain ошибся дважды по одной теме** | Закрой чат, открой новый — стрял в "context rot" |
| **Не редактируй journal/*.md руками** | Только через `scripts/journal.sh ...` или brain. Иначе формат ломается |
| **Не паникуй если slash-команда "Unknown"** | Скажи прямо текстом — brain сделает то же самое |

## 🎓 Тренировочная неделя — что попробовать

**Понедельник:** один полный цикл «Тестируем TRD-X» от утра до save.

**Вторник:** «доброе утро» + два разных тикета в двух чатах. Поймёшь зачем разные чаты.

**Среда:** при работе попробуй спросить «объясни почему так» — посмотришь как orchestrator делится ISTQB-обоснованием.

**Четверг:** в конце дня сравни `journal/<сегодня>.md` с тем что ты помнишь — насколько brain поймал работу. Если упустил что-то существенное — скажи в чате, brain учится.

**Пятница:** weekly retro. Сядь, прочитай `journal/<вчера>.md`, скажи что хочешь поправить в правилах. Я обновлю persona.

## 🧹 Раз в неделю — clean MCP orphans

Claude Code не убивает MCP-серверы корректно при закрытии чата. После каждой закрытой сессии остаётся 2 python-процесса (~50MB каждый). За неделю накапливается ~700MB.

```bash
scripts/cleanup-mcp-zombies.sh --dry-run   # просто проверить
scripts/cleanup-mcp-zombies.sh             # очистить orphans, не трогать live
```

Скрипт безопасный — кладёт **только orphans** (parent=launchd или parent не claude). Свои live-процессы текущей сессии оставляет в живых.

Вписать в weekly retro: в пятницу в build slot — `cleanup-mcp-zombies.sh`, потом `brain-stats history`.

## 🆘 Если что-то совсем не работает

**MCP отвалились / brain не видит YouTrack:**
```bash
claude mcp list
```
Проверь что плагины ✅ Connected.

**KB устарел / brain думает что v2.9 актуальна:**
```bash
.venv/bin/python scripts/update-kb.py
```

**Не помнишь как что-то сделать:**
```
прочитай HOWTO.md
```

→ Brain прочитает этот файл и подскажет нужный сценарий.
